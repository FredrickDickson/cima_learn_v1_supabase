# **2. Payment Flow with Paystack**

**Step-by-step transaction:**

1. **Student clicks “Enroll”**
2. **Frontend triggers Paystack Checkout**

   * Parameters: amount, email, course reference
3. **Paystack handles payment** (cards, bank, USSD)
4. **Paystack returns result**

   * Success → webhook triggered to backend
   * Failure → show error message
5. **Backend verifies transaction**

   * Uses Paystack API to confirm payment
   * Updates `enrollments` table
6. **Student gains course access**
7. **Transaction recorded**

   ```text
   transaction_id | student_id | course_id | amount | status | date
   ```

💡 **Notes:**

* Use **webhooks** for security: only grant access after server verification.
* Optional: send **email receipt** to student.

# **3. Database Design (Simplified)**

**Tables:**

1. **Users**

   * id, name, email, role (student/instructor/admin), password\_hash, profile\_pic
2. **Courses**

   * id, title, description, category, instructor\_id, price, is\_published, thumbnail
3. **Sections**

   * id, course\_id, title, order
4. **Lessons**

   * id, section\_id, title, type (video/pdf/text), content\_url, order
5. **Enrollments**

   * id, student\_id, course\_id, enrollment\_date, status
6. **Transactions**

   * id, student\_id, course\_id, transaction\_id, amount, status, date
7. **Reviews**

   * id, student\_id, course\_id, rating, comment, date
8. **Quizzes/Assignments**

   * id, course\_id, type, questions, answers
9. **Admin Logs** (optional)

   * id, action, performed\_by, date
